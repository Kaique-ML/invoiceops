# Decisions and evidence

| Decision | Reason / alternative | Source and version checked | Evidence |
|---|---|---|---|
| Use Python 3.12 in Linux containers. | Python 3.14.4 exists on the host, but the selected Celery release does not list 3.14 in its current PyPI classifiers; Python 3.11 was listed by the launcher but its executable path was absent. A pinned 3.12 image was pulled and run. | PyPI metadata for Celery 5.6.3; Docker image `python:3.12-slim`, digest `sha256:eeb8088e67610b37583880c7627e3931f087cba55a35810819e34a398f624a47`. | A real Python 3.12 container completed the OCR, schema and queue proof recorded in `docs/progress.md`. |
| Use FastAPI 0.142.2, Pydantic 2.13.5, SQLAlchemy 2.1.1 and Alembic 1.20.0. | One typed API/ORM/migration stack; not a combination of competing frameworks. | Official [FastAPI](https://fastapi.tiangolo.com/), [SQLAlchemy 2.0 documentation](https://docs.sqlalchemy.org/en/20/); PyPI metadata for the exact package releases above. | Versions were checked against PyPI metadata. Application-level integration remains to be tested. |
| Use `pypdf` 6.19.0 for PDF text, `pypdfium2` 5.13.0 for rasterization, Pillow 11.3.0 and pytesseract 0.3.13 with Tesseract. | Keeps parsing/rendering/OCR responsibilities small. PyMuPDF was rejected for this foundation because its OCR path requires separate Tesseract and its licensing model would require a distribution decision. | Official [pypdf text extraction](https://pypdf.readthedocs.io/en/stable/user/extract-text.html) and [pypdfium2 documentation](https://pypdfium2.readthedocs.io/en/stable/); PyPI release metadata. | A synthetic text PDF and a genuinely image-only PDF were processed in a Python 3.12 Linux container; OCR found the expected synthetic invoice text. |
| Use Celery 5.6.3 and Redis 7.4 for the worker transport. | The supported worker queue is tested with a real worker rather than eager mode; Redis is not the source of truth. | [Celery 5.6 task/acknowledgement guide](https://docs.celeryq.dev/en/stable/userguide/tasks.html) and [configuration guide](https://docs.celeryq.dev/en/stable/userguide/configuration.html); images pinned by digest. | A JSON-serialized task was consumed by a real Celery 5.6.3 worker backed by Redis; the result was `42`. Celery acknowledges early by default; application work must therefore be idempotent. |
| Keep Ollama as an optional local structured-output provider. | Avoid paid hosted APIs and do not make local model downloads implicit. An Ollama server/model was not available and weights were not downloaded. | [Ollama structured outputs](https://docs.ollama.com/capabilities/structured-outputs); Ollama Python SDK 0.6.3 metadata and `Client.chat` signature. | Pydantic JSON Schema generation/validation and SDK signature were checked; no model call has been made. |
| Use PostgreSQL 17.11 and Redis 7.4 images pinned by observed registry digests. | Prevent mutable tags and keep state in PostgreSQL rather than SQLite. | [Docker Compose Specification](https://docs.docker.com/reference/compose-file/); pulled images `postgres:17.11-alpine` and `redis:7.4-alpine`. | Registry pulls succeeded; Compose startup/migrations are still pending. |
| Treat integration-owned n8n tables as outside Alembic metadata. | `alembic check` must detect application drift without proposing deletion of a receiver table created by `integrations/n8n/setup.sql`. Prefix ownership was chosen over adopting the external table into application models. | Alembic 1.20.0 autogenerate `include_name` hook. | Repeat upgrade and drift check passed while preserving an existing `invoiceops_n8n_demo_records` table. |
| Pin CI actions to verified releases. | Use explicit releases and read-only repository permission; do not depend on floating major tags. | Official GitHub releases queried 2026-10-05: `actions/checkout@v7.0.1`, `actions/setup-python@v7.0.0`, `astral-sh/setup-uv@v10.2.0`. | Workflow committed in `.github/workflows/ci.yml`; remote execution is recorded separately. |

## Compatibility proof

The proof ran inside the observed Python 3.12 image on 2026-10-01 (local time; container reported 2026-10-02 UTC). It generated synthetic PDFs in memory, used real Tesseract OCR, validated a Pydantic model from JSON, and ran a Celery worker against a disposable Redis container. The first proof attempt exposed an incorrect ReportLab image-wrapper call; the probe was corrected and rerun successfully. This proves those narrow component paths only, not the finished application or live Ollama extraction.
